
# **Short Questions**:-

## Playwright: 
- It is a Node.js library to automate Chromium, Firefox and Webkit with a single API.

## Webkit: 
- Webkit is a browser engine developed by Apple and used in it's Safari and Web browsers.

## Chromium: 
- Chromium is a browser engine used in Edge, Google Chrome.

## Advantages:
 - Fast and reliable
 - Supports Chromium, Firefox, and WebKit
 - Auto-waiting for elements
 - Supports JavaScript, TypeScript, Python, Java, and C#
 - Parallel test execution
 - Good for CI/CD integration

## Context:
- Browser Context is an isolated browser session/profile that allows Playwright to run independent users or tests within the same browser instance.
- One Context has it's own cookies, permissions, locale, timezone, user agent, proxy, and storage state.
- **Headless** : By default chromium is headless : true, if we pass it true, we can see automation on screen, else it works on background.

## Page:
- Page = One browser tab
- A Page belongs to a Browser Context
- Used to interact with a web page/application
- Can navigate, click, fill forms, take screenshots, etc.

## **Locator:**
```
<button id="login" class="btn-primary" data-testid="login-button" title="Login">Login</button>
```
Then get details by:
```
- By role: await page.getByRole('button', { name: 'Login' }).click();
- By text: await page.getByText('Login').click(); or, await page.click("'Login'");
- By id: await page.locator('#login').click();
- By class: await page.locator('.btn-primary').click();
- By CSS: await page.locator('button[id="login"]').click();
- By XPath: await page.locator('//button[@id="login"]').click();
- By Test-id: await page.getByTestId('login-button').click();
- By Title: await page.getByTitle('Login').click();
```

### Use locators in roughly this order:
Role → Label → Test ID → Text → Placeholder → CSS → XPath

> [!NOTE]
> ### textContent() vs innerText():
> - innerText() : Returns the visible text as it is rendered on the page.
> - textContent() : Returns the text content inside the element, including text that may be hidden.
> ```
>let's: 
> <div class="message"> 
>     Hello 
>     <span style="display:none">Hidden Text</span> 
> </div>
> ```
> - const text = await page.locator('.message').innerText(); -> Hello
> - const text = await page.locator('.message').textContent(); -> Hello Hidden Text

## **Playwright Config:**
- playwright.config.ts is the central configuration file that defines how Playwright tests are discovered, executed, debugged, reported, and run across different browsers and environments.

### testDir:
- Defines where Playwright looks for test files.
```
testDir: './tests',
```

### testMatch:
- Controls which files are considered test files.
```
testMatch: '**/*.spec.ts',

Examples:
login.spec.ts
```

### testIgnore:
- Excludes files from test execution.
```
testIgnore: '**/old/**',
```

### timeout:
- Maximum time allowed for a single test in milisec.

### expect:
- Controls assertion timeout in milisec.
```
expect: {
  timeout: 5000,
},

Example:
await expect(page.getByText('Login')).toBeVisible();

Playwright waits up to the configured expectation timeout.
```

### use:
- use contains settings applied to tests.
```
use: {
  baseURL: 'https://example.com',
  headless: true,
  screenshot: 'only-on-failure'
},
```

<summary><b>baseURL:</b></summary>

- Defines the application's base URL.
```bash
use: {
  baseURL: 'https://example.com',
},

Then:
await page.goto('/login');

Playwright opens:
https://example.com/login
```

</details>

<details>
<summary><b>headless:</b></summary>

- Controls whether the browser UI is visible.

</details>

<details>
<summary><b>viewport:</b></summary>

- Controls browser screen size.
```
use: {
  viewport: {
    width: 1280,
    height: 720,
  },
},
```
</details>

<details>
<summary><b>actionTimeout:</b></summary>

- Maximum time for an individual action.
```
use: {
  actionTimeout: 10000,
},
```
</details>

<details>
<summary><b>navigationTimeout:</b></summary>

- Maximum time for navigation.
```
use: {
  navigationTimeout: 30000,
},
```
</details> 

<details>
<summary><b>Screenshot:</b></summary>

- Controls screenshot collection.
```
use: {
  screenshot: 'only-on-failure',
},
```
- Options:
```
'off'
'on'
'only-on-failure'

Recommended:
screenshot: 'only-on-failure'
```
</details>

<details>
<summary><b>Video:</b></summary>

- Records test execution.
```
use: {
  video: 'retain-on-failure',
},
```
- Options include:
```
'off'
'on'
'retain-on-failure'
'on-first-retry'
```
</details>

<details>
<summary><b>Trace:</b></summary>

- Trace is extremely useful for debugging failures.
```
use: {
  trace: 'on-first-retry',
},
```
Trace can contain:
- Actions
- Screenshots
- Network activity
- DOM snapshots
- Console information
```
You can inspect it using:
npx playwright show-trace trace.zip
```
</details>

### browserName:
- You normally configure browsers through projects.
```
projects: [
  {
    name: 'chromium',
    use: { ...devices['Desktop Chrome'] },
  },
],
```

### Multiple Browsers:
- You can run the same tests against different browsers.
```
projects: [
  {
    name: 'chromium',
    use: { ...devices['Desktop Chrome'] },
  },

  {
    name: 'firefox',
    use: { ...devices['Desktop Firefox'] },
  },

  {
    name: 'webkit',
    use: { ...devices['Desktop Safari'] },
  },
],
```

### Device Testing
- Playwright provides predefined devices.
```
projects: [
  {
    name: 'Mobile Chrome',
    use: { ...devices['Pixel 5'] },
  },

  {
    name: 'Mobile Safari',
    use: { ...devices['iPhone 13'] },
  },
],
```

### retries:
- Controls how many times a failed test is retried.
```
retries: 2,
```

### workers:
- Controls how many workers run tests in parallel.
```
workers: 4,
```

### fullyParallel:
- Allows tests to run fully in parallel.
```
fullyParallel: true,
Useful for reducing execution time.
But tests should be independent before enabling aggressive parallelism.
```

### reporter:
- Controls test reports.
```
HTML report:
reporter: [['html']],
```
also can user output file path as:
```
reporter: [['html', {
    outputFile:"filepath"
}]],
```
- Multiple reporters:
```
reporter: [
  ['html'],
  ['list'],
],
```
- Common reporters:
```
list
line
dot
html
json
junit
```

### outputDir:
- Defines where test artifacts are stored.
```
outputDir: './test-results',

Example:

test-results/
├── screenshots
├── videos
└── traces
```

### webServer:
- Automatically starts your application before tests.

For example, if your application runs with:
npm run dev
```
webServer: {
  command: 'npm run dev',
  url: 'http://localhost:3000',
  reuseExistingServer: true,
},
```
Then:
```
npx playwright test
```
will start the application before testing.

### Authentication / Storage State:
- You can reuse a logged-in session.
```
use: {
  storageState: 'playwright/.auth/user.json',
},
```
Example:

Login once
    ↓
Save cookies/session
    ↓
user.json
    ↓
Reuse in tests

This is very useful for enterprise applications.

### Environment Variables:

- You can use environment variables:
```
use: {
  baseURL: process.env.BASE_URL,
},
```
Run:
```
BASE_URL=https://test.example.com 
npx playwright test
```
On Windows PowerShell:
```
$env:BASE_URL="https://test.example.com"
npx playwright test
```
Useful for:

- DEV
- QA
- UAT
- PROD

### globalSetup:
- Runs setup before the test suite.
```
globalSetup: require.resolve('./global-setup'),
```
Useful for:

- Creating test data
- Authentication
- Database preparation
- Environment setup

### globalTeardown
- Runs after the test suite.
```
globalTeardown: require.resolve('./global-teardown'),
```
Useful for cleanup.

### projects
- One of the most powerful configuration features.
- A project represents a different test configuration.

Example:
```
projects: [
  {
    name: 'chromium',
    use: { ...devices['Desktop Chrome'] },
  },
  { 
    name: 'firefox', 
    use: { ...devices['Desktop Firefox'] }, 
    },
],
```
Run only Chromium:
```
npx playwright test --project=chromium
```
