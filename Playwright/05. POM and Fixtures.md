# **POM and Fixtures**

## Page Object Model (POM)

- POM is a **design pattern** used in test automation.
- It is similar to an **OOP class**.
- Each webpage or major component is represented by a separate class.
- The class stores:
  - Page locators
  - Reusable methods
  - Page-specific actions
  - Page-specific validations

### Structure

```text
LoginPage Class
│
├── Locators
│   ├── username
│   ├── password
│   └── loginButton
│
└── Methods
    ├── goto()
    ├── login()
    └── verifyLogin()
```

### Example

```typescript
class LoginPage {

    readonly username;
    readonly password;
    readonly loginButton;

    constructor(page: Page) {
        this.username = page.locator('#username');
        this.password = page.locator('#password');
        this.loginButton = page.getByRole('button', { name: 'Login' });
    }

    async login(user: string, pass: string) {
        await this.username.fill(user);
        await this.password.fill(pass);
        await this.loginButton.click();
    }
}
```

### Usage

```typescript
const loginPage = new LoginPage(page);

await loginPage.login('admin', '1234');
```

### Important

- Locators are usually **instance variables**, not `static`.
- They depend on the Playwright `page` object.
- `static` can be used for shared constants that do not depend on the browser instance.

```typescript
static readonly PAGE_NAME = 'Login Page';
```

### Benefits

- Reusable code
- Less duplicate code
- Easy maintenance
- Better readability
- Easy locator updates
- Cleaner test files

### Easy Definition

> **POM = OOP class that contains reusable locators and methods for a specific webpage or component.**

### Easy Memory

```text
Test = WHAT to test

POM = HOW to perform the actions
```

## Fixture in Playwright

- A **Fixture** is a reusable setup/resource that Playwright automatically creates and provides to a test.
- Fixtures help reduce repeated setup code.
- Playwright can also clean up fixtures automatically after the test.

### Example

```typescript id="ex1"
test('Login Test', async ({ page }) => {

    await page.goto('https://example.com');

});
```

Here:

```typescript id="ex2"
page
```

is a **built-in fixture**.

### Common Built-in Fixtures

| Fixture | Purpose |
|---|---|
| `page` | Browser tab/page |
| `context` | Browser session/context |
| `browser` | Browser instance |
| `browserName` | Browser type |
| `request` | API testing |
| `baseURL` | Configured base URL |

### Flow

```text id="ex3"
Playwright
   ↓
Creates Fixture
   ↓
Provides it to Test
   ↓
Test Uses It
   ↓
Cleanup
```

### Custom Fixture

We can create our own fixtures.

Example:

```text id="ex4"
loginPage
userData
apiClient
databaseConnection
```

Instead of:

```typescript id="ex5"
const loginPage = new LoginPage(page);
```

a custom fixture can automatically provide:

```typescript id="ex6"
test('Login Test', async ({ loginPage }) => {

    await loginPage.login('admin', '1234');

});
```

### Fixture + POM

```text id="ex7"
POM
→ Contains locators and reusable page actions

Fixture
→ Creates and provides the POM object to tests
```

Example:

```text id="ex8"
LoginPage
   ↓
Custom Fixture
   ↓
Test receives loginPage
   ↓
Test uses loginPage.login()
```

### Benefits

- Reusable setup
- Less duplicate code
- Automatic setup and cleanup
- Cleaner test files
- Easy dependency management
- Useful for POM integration

### Easy Definition

> **Fixture = A reusable resource or setup that Playwright prepares and provides automatically to a test.**

### Easy Memory

```text id="ex9"
POM = WHAT actions a page can perform

Fixture = PROVIDES resources to the test
```
